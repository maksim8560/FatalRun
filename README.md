# FatalRun

Многопользовательская пати-игра для браузера: приватное лобби по коду до 4 игроков и
мини-игры. Первая мини-игра — паркур (обби) с чекпоинтами и движущимися платформами.

Всё написано с нуля: геометрия генерируется из примитивов, графика рисуется кодом на
`Canvas`, ни один сторонний ассет не используется. Никаких заимствованных моделей,
текстур, персонажей или названий — в проекте нет ничего, что могло бы принадлежать
другому автору.

## Запуск

```bash
npm install
npm start
```

Откройте <http://localhost:3000>. Сервер отдаёт и статику, и WebSocket на одном порту,
поэтому для локальной игры достаточно одного окна терминала.

Проверить протокол без браузера:

```bash
npm test          # или: node tools/smoke.js
```

Тест поднимает четыре WebSocket-клиента и прогоняет полный цикл: лобби, лимит в 4
игрока, отсчёт, чекпоинты, порядок финиша, начисление очков, возврат в лобби, обрыв
соединения.

## Управление

| Действие | Клавиши |
| --- | --- |
| Движение | `W` `A` `S` `D` или стрелки `↑` `↓` |
| Камера | мышь (клик — захват, `Esc` — отпустить) |
| Камера без захвата | зажать и тянуть мышью |
| Камера с клавиатуры | `Q` / `E` или `←` / `→` |
| Прыжок | `Пробел` |
| Бег | `Shift` |
| Пауза и выход | `Esc` |
| Подсказка по управлению | `H` |
| Ники над головами | `N` |

Камера полностью ручная: она не доворачивается за персонажем и не «догоняет» его
направление. Движение всегда относительно взгляда.

## Как играть

1. Введите ник и нажмите **Создать комнату** — сервер выдаст четырёхсимвольный код.
2. Друзья открывают тот же адрес, вводят код и жмут **Войти**. Лимит — 4 игрока.
3. Хост нажимает **Начать раунд**. Идёт отсчёт, стены лобби исчезают, игроки бегут
   трассу.
4. Победа — финишный чекпоинт. Первый финишер получает 4 очка, последний — 1 или 0.
   Очки накапливаются между раундами.
5. После финиша всех или по истечении двух минут раунд закрывается, показываются
   места, и игра возвращается в лобби.

`Esc` во время раунда открывает паузу: продолжить или выйти. При выходе игрок
освобождает слот, слот тут же занимает кто-то другой.

## Устройство проекта

```
server/
  index.js    HTTP + статика + WebSocket, heartbeat, автосбор пустых комнат
  rooms.js    состояние комнат и раундов, валидация всего, что приходит от клиента
shared/
  config.js   общие настройки: лимит игроков, тайминги, физика, чувствительность
  track.js    детерминированный генератор трассы по seed
public/
  index.html  экраны меню, лобби, паузы, результатов и HUD
  js/
    main.js       сборка всего вместе, игровой цикл, сетевой обмен
    net.js        WebSocket, смещение часов, автопереподключение
    scene.js      рендерер, камера, свет, туман
    trackView.js  меши трассы и коллизии
    player.js     ввод, камера, столкновения, физика
    avatar.js     блочный персонаж и никнейм
    remotes.js    интерполяция чужих игроков
    ui.js         все экраны
tools/
  smoke.js   протокольный тест на четырёх клиентах
```

### Кто что решает

Сервер — единственный источник правды по лобби, фазе, чекпоинтам и порядку финиша.
Клиент считает только свою физику и присылает результат.

Трасса не передаётся по сети: и сервер, и каждый клиент строят её из одного целого
`seed`, который выводится из кода комнаты. Поэтому трасса всегда одинаковая, а лишнего
трафика нет.

Защита от подмены позиции: сервер отклоняет пакет, в котором игрок сместился больше чем
на 24 stud за раз, и отправляет клиенту команду вернуться на свою позицию. Заявление о
чекпоинте или финише проверяется по расстоянию до настоящей точки — просто «сообщить», что
ты дошёл, нельзя.

### Добавление мини-игры

Один цикл раунда обслуживает любую мини-игру. Нужно:

1. Добавить генерацию геометрии в `shared/track.js` по новому `seed` (или отдельной
   функции для нового типа игры).
2. Описать в `server/rooms.js`, как игрок засчитывает прохождение — новый тип сообщения в
   `handleMessage` с проверкой расстояния, как у `cp` и `finish`.
3. Добавить проверку прогресса в `checkProgress` в `public/js/main.js`.

Рендерер, физика, лобби, пауза, выход, интерполяция и результаты при этом не меняются.

## Развёртывание

Сервер не пишет на диск и не хранит состояние, поэтому подойдёт любой хост с Node 20+.

```bash
PORT=8080 HOST=0.0.0.0 node server/index.js
```

`HOST=0.0.0.0` нужен, чтобы сервер был доступен не только с localhost. Если фронтенд и
бэкенд разводят по разным доменам, WebSocket должен идти на тот же адрес, что и страница —
клиент подключается к `ws://<текущий хост>/ws` автоматически, отдельная настройка не нужна.

Для игры по интернету нужен HTTPS: браузер включает захват мыши только в защищённом
контексте. За `nginx` или любым другим терминатором нужен апгрейд на WebSocket.

## Ограничения текущей версии

- Одна мини-игра — паркур. Остальные добавляются по схеме выше.
- Нет чата и голоса.
- Нет аккаунтов: игрок идентифицируется ником, который можно сменить перезаходом.
- Позиции считаются на клиенте. Для игры с друзьями этого достаточно, но для
  соревновательного режима понадобится серверная симуляция.
